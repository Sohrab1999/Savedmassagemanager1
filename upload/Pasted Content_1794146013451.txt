ISSUE 1 — Telegram Provenance: Correcting the Trust Claim
1.1 Explicit Taxonomy of the Four Concepts
Concept	Definition	Security Property
1. Deterministic Source Identity	Canonical string tuple tgv1:<firebase_uid>:<telegram_user_id>:<telegram_chat_id>:<telegram_message_id> constructed from lossless base-10 Telegram ID strings.	Uniquely identifies a specific Telegram message for a linked user without JavaScript Number precision loss.
2. Collision-Resistant Document ID	firestore_note_id = "${userPrefix}_tgv1_${telegramMessageId}_${sha256Hex(sourceIdentity).slice(0, 40)}" (68..86 ASCII chars).	Maps a variable-length source identity into a fixed-bound (<= 86 chars 
) Firestore document ID with 
 collision resistance across users/chats/messages. Note: An unkeyed SHA-256 hash is a public digest, NOT a cryptographic MAC.
3. Application-Level Provenance Convention	Reserving the _tgv1_ document ID infix exclusively for importStagedNoteToFirestore() while blocking _tgv1_ in createFirestoreNote() and generateSafeId('note').	Prevents accidental collisions or overwrites between normal UI actions (Quick Capture, sample sync, retry loops) within the cooperative client application.
4. Cryptographically Authenticated Provenance	Proof enforced by a trusted write boundary that a Firestore document could only have been created from an authentic Telegram webhook.	Cannot be achieved inside /notes/{noteId} under client-mediated Firestore writes, because the browser holds the user's Firebase Web SDK credentials.
1.2 Inspection of /firestore.rules: Can a Client Directly Create a _tgv1_ Document?
Verified Fact from /firestore.rules (lines 23–25, 82–114, 175–178):
allow create on /notes/{noteId} checks isSignedIn() && isValidId(noteId) && isValidSavedNote(incoming(), noteId) && incoming().createdAt == request.time && incoming().updatedAt == request.time.
isValidId(noteId) checks only id is string && id.size() >= 1 && id.size() <= 128 && id.matches('^[a-zA-Z0-9_\\-]+$').
Conclusion: Under the existing /firestore.rules, any authenticated user (request.auth.uid == userId) running custom JavaScript in their browser DevTools can directly call setDoc(doc(db, 'notes', '<uidPrefix>_tgv1_...'), validPayload) to create a document with a _tgv1_ ID in their own user library. Therefore, an existing _tgv1_ document in Firestore is an application-level provenance convention, not cryptographic proof against a malicious user modifying their own library.

ISSUE 2 — Corrected PostgreSQL PUBLIC & Runtime Privilege Verification
2.1 Why PUBLIC Requires Catalog ACL Expansion (aclexplode)
In PostgreSQL, PUBLIC is not an ordinary role in pg_catalog.pg_roles (verified live: SELECT COUNT(*) FROM pg_catalog.pg_roles WHERE rolname = 'public' returns 0). In internal aclitem[] arrays (datacl, nspacl, relacl, defaclacl), grants to PUBLIC are stored with grantee = 0::oid.
Furthermore, calling has_database_privilege(current_user, ...) or has_table_privilege(current_user, ...) reports effective privileges (combining direct grants to current_user, inherited role grants such as pg_read_all_data / pg_write_all_data, and grants to PUBLIC), whereas inspecting aclexplode(COALESCE(acl_col, acldefault(...))) inspects direct ACL entries (grantee = 0::oid for PUBLIC, grantee = current_user::regrole::oid for direct user grants).
Both effective privilege checks and direct catalog ACL inspections are required and provided in Section 4 below.
ISSUE 3 — Expired Lease Recovery & Dead-Letter Correctness
3.1 Complete State Machine for telegram_staged_notes
Every row in public.telegram_staged_notes is in one of three states (state IN ('staged', 'claimed', 'failed')):
State	delivery_attempts	claim_lease_id	lease_expires_at	failed_at	last_error_code	Meaning
'staged' (Initial)	0	NULL	NULL	NULL	NULL	Newly ingested from webhook; ready for first claim.
'staged' (Recovered after expired lease 1..4)	1..4	NULL	NULL	NULL	'lease_expired_requeued' (or transient code)	Lease 1..4 expired without ack; recovered by Step E.1b and ready for next claim.
'claimed' (Active Lease)	1..5	'lease_<32hex>'	NOT NULL (now + 60s)	NULL	NULL or prior transient code	Actively leased to a client claim batch; increments delivery_attempts by +1 on claim.
'failed' (Dead-Letter)	1..5	NULL	NULL	NOT NULL	NOT NULL (1..64 chars)	Reached 5 expired attempts OR client reported permanent failure; held for 14 days for inspection/retry/dismissal.
(Full transactional SQL for all lease, recovery, dead-letter, partial ack, retry, and dismissal operations is provided in Section 6 below.)

        d.datname AS db_name,

Query 3 — Role Attributes, Recursive INHERIT / SET ROLE Paths, & Owner Non-Membership
SQL
WITH RECURSIVE role_tree AS (
    SELECT
        am.member AS member_oid,
        am.roleid AS granted_oid,
        am.admin_option,
        am.inherit_option,
        am.set_option,
        1 AS depth
    FROM pg_catalog.pg_auth_members am
    WHERE am.member = current_user::regrole
    UNION ALL
    SELECT
        am.member,
        am.roleid,
        am.admin_option,
        am.inherit_option,
        am.set_option,
        rt.depth + 1
    FROM pg_catalog.pg_auth_members am
    JOIN role_tree rt ON am.member = rt.granted_oid
)
SELECT
    r.rolname AS current_role_name,
    r.rolsuper,
    r.rolinherit,
    r.rolcreaterole,
    r.rolcreatedb,
    r.rolbypassrls,
    pg_has_role(current_user, (SELECT datdba FROM pg_catalog.pg_database WHERE datname = current_database()), 'USAGE') AS can_use_db_owner,
    pg_has_role(current_user, (SELECT datdba FROM pg_catalog.pg_database WHERE datname = current_database()), 'MEMBER') AS can_set_role_db_owner,
    pg_has_role(current_user, (SELECT nspowner FROM pg_catalog.pg_namespace WHERE nspname = 'public'), 'USAGE') AS can_use_schema_owner,
    pg_has_role(current_user, (SELECT nspowner FROM pg_catalog.pg_namespace WHERE nspname = 'public'), 'MEMBER') AS can_set_role_schema_owner,
    COALESCE(
        (SELECT jsonb_agg(jsonb_build_object(
            'member', rt.member_oid::regrole::text,
            'granted', rt.granted_oid::regrole::text,
            'inherit', rt.inherit_option,
            'set_role', rt.set_option,
            'admin', rt.admin_option,
            'depth', rt.depth
        ) ORDER BY rt.depth, rt.granted_oid::regrole::text) FROM role_tree rt),
        '[]'::jsonb
    ) AS role_memberships
FROM pg_catalog.pg_roles r
WHERE r.rolname = current_user;
Expected Post-Gate-2B.1B Result: rolsuper, rolcreaterole, rolcreatedb, rolbypassrls, can_use_db_owner, can_set_role_db_owner, can_use_schema_owner, can_set_role_schema_owner MUST all be false.
Query 4 — Table, Index, & Sequence Ownership, Effective Privileges, & Direct ACL Inspection
SQL
WITH obj_info AS (
    SELECT
        c.oid AS obj_oid,
        n.nspname AS schema_name,
        c.relname AS object_name,
        c.relkind AS object_kind,
        c.relowner AS owner_oid,
        pg_catalog.pg_get_userbyid(c.relowner) AS object_owner,
        COALESCE(
            c.relacl,
            acldefault(
                CASE WHEN c.relkind = 'S' THEN 's'::"char" ELSE 'r'::"char" END,
                c.relowner
            )
        ) AS effective_acl
    FROM pg_catalog.pg_class c
    JOIN pg_catalog.pg_namespace n ON n.oid = c.relnamespace
    WHERE n.nspname = 'public'
      AND c.relkind IN ('r', 'p', 'v', 'm', 'S', 'i')
)
SELECT
    oi.object_name,
    oi.object_kind,
    oi.object_owner,
    pg_has_role(current_user, oi.owner_oid, 'USAGE') AS eff_user_is_owner,
    pg_has_role(current_user, oi.owner_oid, 'MEMBER') AS eff_user_can_set_role_owner,
    CASE WHEN oi.object_kind IN ('r', 'p', 'v', 'm') THEN has_table_privilege(current_user, oi.obj_oid, 'SELECT') ELSE NULL END AS eff_select,
    CASE WHEN oi.object_kind IN ('r', 'p', 'v', 'm') THEN has_table_privilege(current_user, oi.obj_oid, 'INSERT') ELSE NULL END AS eff_insert,
    CASE WHEN oi.object_kind IN ('r', 'p', 'v', 'm') THEN has_table_privilege(current_user, oi.obj_oid, 'UPDATE') ELSE NULL END AS eff_update,
    CASE WHEN oi.object_kind IN ('r', 'p', 'v', 'm') THEN has_table_privilege(current_user, oi.obj_oid, 'DELETE') ELSE NULL END AS eff_delete,
    CASE WHEN oi.object_kind IN ('r', 'p', 'v', 'm') THEN has_table_privilege(current_user, oi.obj_oid, 'TRUNCATE') ELSE NULL END AS eff_truncate,
    CASE WHEN oi.object_kind IN ('r', 'p', 'v', 'm') THEN has_table_privilege(current_user, oi.obj_oid, 'REFERENCES') ELSE NULL END AS eff_references,
    CASE WHEN oi.object_kind IN ('r', 'p', 'v', 'm') THEN has_table_privilege(current_user, oi.obj_oid, 'TRIGGER') ELSE NULL END AS eff_trigger,
    COALESCE(
        (SELECT jsonb_agg(acl.privilege_type ORDER BY acl.privilege_type)
         FROM aclexplode(oi.effective_acl) AS acl
         WHERE acl.grantee = 0::oid),
        '[]'::jsonb
    ) AS acl_public_privileges,
    COALESCE(
        (SELECT jsonb_agg(acl.privilege_type ORDER BY acl.privilege_type)
         FROM aclexplode(oi.effective_acl) AS acl
         WHERE acl.grantee = current_user::regrole::oid),
        '[]'::jsonb
    ) AS acl_direct_user_privileges
FROM obj_info oi
ORDER BY oi.object_kind, oi.object_name;

6. Complete Transaction Pseudocode for Staged Note & Lease Lifecycle (Issue 3)
6.1 Lock Order & Index Coverage Across All Staged-Note Transactions
Parent Table Lock First: Every transaction that mutates telegram_staged_notes on behalf of a user (Webhook Stage, Claim, Ack/Fail, Retry, Dismiss, Unlink) locks the user's parent row in public.telegram_account_links first (FOR NO KEY UPDATE for webhook staging to serialize the 100-row cap; FOR KEY SHARE for Claim, Ack/Fail, Retry, Dismiss; FOR UPDATE via DELETE for Unlink).

6.3 Expired Lease Recovery (Attempts 1..4), 5th-Attempt Dead-Letter Transition, & Batch Claim (POST /api/telegram/staged/claim — Requirements 1, 2, 3, 4, 5, 6)
Precondition: Backend verifies Firebase ID token (firebase_uid = $1) and generates claimLeaseId = 'lease_' + crypto.randomBytes(16).toString('hex') ($2) on the server.
SQL
BEGIN;

-- 1. Lock parent link row (FOR KEY SHARE) to coordinate with Unlink
SELECT firebase_uid
FROM public.telegram_account_links
WHERE firebase_uid = $1
FOR KEY SHARE;
-- If 0 rows returned -> COMMIT and return { claimLeaseId: null, notes: [] }.

-- 2. Transition expired 5th-attempt leases (delivery_attempts = 5) to terminal 'failed' state
WITH expired_fifth AS (
    SELECT firestore_note_id
    FROM public.telegram_staged_notes
    WHERE firebase_uid = $1
      AND state = 'claimed'
      AND lease_expires_at <= clock_timestamp()
      AND delivery_attempts >= 5
    ORDER BY firestore_note_id ASC
    FOR UPDATE SKIP LOCKED
)
UPDATE public.telegram_staged_notes AS n
SET state = 'failed',
    claim_lease_id = NULL,
    lease_expires_at = NULL,
    failed_at = clock_timestamp(),
    last_error_code = COALESCE(n.last_error_code, 'max_delivery_attempts_exceeded'),
    expires_at = GREATEST(n.expires_at, clock_timestamp() + INTERVAL '14 days')
FROM expired_fifth
WHERE n.firestore_note_id = expired_fifth.firestore_note_id;

-- 3. Recover expired leases from attempts 1..4 back to 'staged' (preserving delivery_attempts 1..4)
WITH expired_recoverable AS (
    SELECT firestore_note_id
    FROM public.telegram_staged_notes
    WHERE firebase_uid = $1
      AND state = 'claimed'
      AND lease_expires_at <= clock_timestamp()
      AND delivery_attempts BETWEEN 1 AND 4
    ORDER BY firestore_note_id ASC
    FOR UPDATE SKIP LOCKED
)
UPDATE public.telegram_staged_notes AS n
SET state = 'staged',
    claim_lease_id = NULL,
    lease_expires_at = NULL,
    last_error_code = COALESCE(n.last_error_code, 'lease_expired_requeued')
FROM expired_recoverable
WHERE n.firestore_note_id = expired_recoverable.firestore_note_id;

-- 4. Claim up to 20 'staged' rows (both initial attempts = 0 and recovered attempts = 1..4)
--    using FOR UPDATE SKIP LOCKED and increment delivery_attempts by +1 (to 1..5)
WITH claimable AS (
    SELECT firestore_note_id
    FROM public.telegram_staged_notes
    WHERE firebase_uid = $1
      AND state = 'staged'
      AND expires_at > clock_timestamp()
      AND delivery_attempts BETWEEN 0 AND 4
    ORDER BY created_at ASC, firestore_note_id ASC
    LIMIT 20
    FOR UPDATE SKIP LOCKED
)
UPDATE public.telegram_staged_notes AS n
SET state = 'claimed',
    claim_lease_id = $2,
    lease_expires_at = clock_timestamp() + INTERVAL '60 seconds',
    delivery_attempts = n.delivery_attempts + 1
FROM claimable
WHERE n.firestore_note_id = claimable.firestore_note_id
RETURNING
    n.firestore_note_id,
    n.firebase_uid,
    n.telegram_user_id,
    n.telegram_chat_id,
    n.telegram_message_id::text AS telegram_message_id,
    n.title,
    n.content,
    n.description,
    n.content_type,
    n.category_id,
    n.tags_json,
    n.source_name,
    n.source_type,
    n.source_url,
    n.file_name,
    n.file_size,
    n.is_favorite,
    n.is_archived,
    n.delivery_attempts,
    n.claim_lease_id,
    n.lease_expires_at;

COMMIT;
6.4 Partial Acknowledgement, Partial Permanent/Transient Failure, & Stale Lease Rejection (POST /api/telegram/staged/ack — Requirements 7, 8, 12)
Precondition: Authenticated firebase_uid = $1 submits:
claimLeaseId = $2 (^lease_[0-9a-f]{32}$)
acknowledgedNoteIds = $3::text[] (0..20 IDs that succeeded or were verified already_imported in Firestore)
permanentFailedNoteIds = $4::text[] + permanentErrorCode = $5 (0..20 IDs that encountered a permanent validation/provenance conflict or reached delivery_attempts = 5)
(Disjointness check in handler: acknowledgedNoteIds and permanentFailedNoteIds must have zero overlapping IDs).
SQL
BEGIN;

-- 1. Lock parent link row (FOR KEY SHARE)
SELECT firebase_uid
FROM public.telegram_account_links
WHERE firebase_uid = $1
FOR KEY SHARE;

-- 2. Lock all active claimed rows matching this user + active unexpired lease + submitted IDs
--    in deterministic firestore_note_id ASC order
WITH locked_lease_rows AS (
    SELECT firestore_note_id, delivery_attempts
    FROM public.telegram_staged_notes
    WHERE firebase_uid = $1
      AND state = 'claimed'
      AND claim_lease_id = $2
      AND lease_expires_at > clock_timestamp()
      AND firestore_note_id = ANY($3::text[] || $4::text[])
    ORDER BY firestore_note_id ASC
    FOR UPDATE
),
-- 3. Delete acknowledged rows
deleted_acks AS (
    DELETE FROM public.telegram_staged_notes AS n
    USING locked_lease_rows AS l
    WHERE n.firestore_note_id = l.firestore_note_id
      AND n.firestore_note_id = ANY($3::text[])
    RETURNING n.firestore_note_id
),
-- 4. Transition permanently failed rows (or rows on attempt 5) to state = 'failed'
marked_failed AS (
    UPDATE public.telegram_staged_notes AS n
    SET state = 'failed',
        claim_lease_id = NULL,
        lease_expires_at = NULL,
        failed_at = clock_timestamp(),
        last_error_code = $5,
        expires_at = GREATEST(n.expires_at, clock_timestamp() + INTERVAL '14 days')
    FROM locked_lease_rows AS l
    WHERE n.firestore_note_id = l.firestore_note_id
      AND n.firestore_note_id = ANY($4::text[])
    RETURNING n.firestore_note_id
)
SELECT
    COALESCE((SELECT array_agg(firestore_note_id) FROM deleted_acks), ARRAY[]::text[]) AS acked_ids,
    COALESCE((SELECT array_agg(firestore_note_id) FROM marked_failed), ARRAY[]::text[]) AS failed_ids;

COMMIT;
Stale Lease Rejection: Any ID submitted under an expired or mismatched claim_lease_id is excluded by locked_lease_rows (WHERE state = 'claimed' AND claim_lease_id = $2 AND lease_expires_at > clock_timestamp()) and returned in ignoredStaleIds (HTTP 200).
Transient Failures on Attempts 1..4: Any note in the claimed batch that failed due to a transient network timeout is simply omitted from acknowledgedNoteIds and permanentFailedNoteIds; its 60-second lease expires naturally and Step 3 of Claim (Section 6.3) recovers it back to state = 'staged'.
6.5 Retry & Dismissal of Failed Rows Without Racing Claim or Ack (POST /api/telegram/staged/retry & POST /api/telegram/staged/dismiss — Requirements 9, 10)
Because Retry and Dismiss filter strictly on WHERE state = 'failed' (where claim_lease_id IS NULL) while Claim selects WHERE state = 'staged' (or expired 'claimed') and Ack selects WHERE state = 'claimed', Retry and Dismiss operate on a disjoint state (state = 'failed') and use FOR UPDATE SKIP LOCKED in firestore_note_id ASC order:
SQL
-- Retry Transaction (POST /api/telegram/staged/retry)
BEGIN;

SELECT firebase_uid FROM public.telegram_account_links WHERE firebase_uid = $1 FOR KEY SHARE;

WITH target_failed AS (
    SELECT firestore_note_id
    FROM public.telegram_staged_notes
    WHERE firebase_uid = $1
      AND state = 'failed'
      AND expires_at > clock_timestamp()
      AND ($2::text[] IS NULL OR firestore_note_id = ANY($2::text[]))
    ORDER BY firestore_note_id ASC
    LIMIT 20
    FOR UPDATE SKIP LOCKED
)
UPDATE public.telegram_staged_notes AS n
SET state = 'staged',
    claim_lease_id = NULL,
    lease_expires_at = NULL,
    delivery_attempts = 0,
    failed_at = NULL,
    last_error_code = NULL,
    expires_at = clock_timestamp() + INTERVAL '7 days'
FROM target_failed
WHERE n.firestore_note_id = target_failed.firestore_note_id
RETURNING n.firestore_note_id;

COMMIT;

-- Dismiss Transaction (POST /api/telegram/staged/dismiss)
BEGIN;

SELECT firebase_uid FROM public.telegram_account_links WHERE firebase_uid = $1 FOR KEY SHARE;

WITH target_dismiss AS (
    SELECT firestore_note_id
    FROM public.telegram_staged_notes
    WHERE firebase_uid = $1
      AND state = 'failed'
      AND firestore_note_id = ANY($2::text[])
    ORDER BY firestore_note_id ASC
    FOR UPDATE SKIP LOCKED
)
DELETE FROM public.telegram_staged_notes AS n

WHERE n.firestore_note_id = target_dismiss.firestore_note_id
RETURNING n.firestore_note_id;
